# 용어정리 카드 (term-card)

> ⚠️ **먼저 [[lms-safe]]를 적용한다.** 용어 정의·비유·예시를 LMS 원문에서 베끼지 말고, 자체 소화해 내 말로 쓴다(공인 전문용어 자체는 예외). 게시 전 lms-safe 체크리스트 통과.

배운 용어를 조경호 블로그의 고정 3단 템플릿으로 정리한다.
블로그 전 글에서 100% 일관되게 쓰는 형식이므로 **틀을 절대 바꾸지 않는다**.

## 카드 하나의 형식

```markdown
### N. 용어명(English 원어)
- **정의**: 무엇인지 한두 문장. 약어면 원어 풀이를 함께.
- **비유**: 일상에서 바로 떠오르는 비교 하나.
- **예시**: 실제로 어디에 쓰는지 / 주의점 하나.
```

카드가 10개를 넘으면 **갈래로 묶는다**(최근 글들이 쓰는 구조).
`## 갈래 N. 묶음 이름` 아래에 `### N. 용어` 카드를 넣고,
글 앞부분에 갈래별로 어떤 낱말이 들어갔는지 표로 먼저 보여준다.
카드 번호는 갈래가 바뀌어도 **글 전체에서 1부터 연속**으로 매긴다.

규칙:
- 세 줄은 항상 **정의 → 비유 → 예시** 순서, 이 순서를 바꾸지 않는다.
- 핵심 단어는 `**굵게**` 강조(정의 안의 키워드, 예시 안의 조건 등).
- 비유는 계산대·바구니·창고·메모판처럼 **손에 잡히는 사물**로. 추상적 비유 금지.
- 원어(영어)는 `*이탤릭*` 또는 괄호로 병기.
- **용어를 비유로 대체하지 않는다.** 정의는 정확한 용어로 쓰고, 비유는 그 아래 한 줄 보조다.
  용어정리 글은 3단 형식이 블로그 전체의 일관성이므로 「비유」 줄 자체는 유지하되,
  억지로 갖다 붙이지는 않는다. 마땅한 비유가 없으면 **개념 간 대비**로 대신한다
  (예: "Schema는 데이터 전체의 구조 / Argument Schema는 함수 입력값의 구조").

## 실제 예시 (블로그 원본 톤)

```markdown
### 1. 캐시(Cache)
- **정의**: 자주 쓰는 데이터를 **메모리에 잠깐** 두어 빠르게 꺼내 쓰는 것.
- **비유**: 매번 창고(디스크·DB)까지 안 가고, 자주 찾는 물건을 **계산대 옆 바구니**에 올려 둠.
- **예시**: 로그인 세션 확인. 대신 원본과 잠깐 어긋날 수 있어 **수명(TTL)** 을 정해 둔다.
```

## 이미 정리한 용어가 또 나오면 — 「다시 정리」 표시 (2026-08-27 도입)

**이전 용어정리 글에서 카드로 정리한 용어가 다시 나오면, 지우지 말고 표시해서 다시 싣는다.**
같은 용어가 몇 번째인지는 그 자체로 정보다.

카드 제목 바로 아래에 인용 블록으로 붙인다.

```markdown
### 9. Schema(스키마)
> ※ 다시 정리 — **세 번째.** 7월과 8월에 정리했다.
- **정의**: ...
```

규칙:
- 문구는 **`※ 다시 정리 — N번째`**. "중복"이라고 쓰지 않는다 —
  「중복」은 쓸데없이 또 나왔다는 뜻으로 읽히고 글쓴이를 깎는다. 반복은 복습이다.
- **횟수를 센 기준은 「용어정리 글에서 카드로 정리한 것」만.** 다른 글 본문에서
  지나가듯 쓴 것은 정리한 게 아니므로 세지 않는다.
- 언제 정리했는지 한 조각 덧붙인다(예: "7월에 정리했다").
- **표시만 하고 정의는 새로 쓴다.** 이전 글 문장을 복사하지 않는다.

### 다섯 번을 넘기면 횟수를 적지 않는다 (2026-09-07 추가)

**표시는 두 번째~네 번째까지만 붙인다.** 다섯 번째 이상이면 **카드는 싣고
「다시 정리」 줄은 쓰지 않는다.**

이유 — 두 번째·세 번째는 **어디로 옮겨 물었는지가 보인다.** 7월엔 CLI(조작
방식)를, 9월엔 CLI 툴(그 방식으로 도는 프로그램)을 물은 것처럼 층위가 한 칸
움직인 게 드러난다. 그런데 다섯 번을 넘어가면 숫자가 **"자주 나온다"는 뜻밖에
없다.** 정보가 아니라 집계가 된다.

- 세어는 본다. 다섯 번을 넘긴 것을 **아는 것**과 글에 **싣는 것**은 다르다.
- 마무리에서 "몇 개가 두 번째 이상인가"는 계속 쓴다. 다만 다섯 번을 넘긴
  낱말은 "횟수를 적지 않았다"고만 밝히고 숫자를 쓰지 않는다.
- 그 낱말을 **왜 여러 번 물었는지 지어내지 않는다.** 위 「반복의 이유를
  지어내지 않는다」가 그대로 적용된다.

2026-09-07 글에서 GenAI가 다섯 번을 넘겨 처음 적용했다.

### ⚠️ 반복의 이유를 지어내지 않는다 (2026-09-05 개정)

**2026-08-27~2026-09-05 사이, 이 스킬은 반복을 결핍으로만 읽었다.**
"두 번 정리했는데 또 물었다", "지금 가장 약한 자리다" 같은 문구가 예시로 박혀 있어서,
글이 반복을 볼 때마다 원인을 하나로 단정했다. 원인은 최소 셋이다.

| 이유 | 무엇인가 |
|---|---|
| **복습** | 강의에서 자주 나오는 용어라, 머릿속에 한 번 더 자리잡히고 수업을 들으려는 것. **의도된 반복이다.** |
| **갱신** | 같은 낱말인데 층위·맥락이 달라진 것. 예: 「에이전트」가 7월엔 하네스를 씌운 도구, 9월엔 스스로 도구를 고르는 실행 주체. 다시 정리한 게 아니라 **다른 것을 정리한 것**이다. |
| **약점** | 아직 손에 안 붙은 것. |

**기본값은 「약점」이 아니라 「묻는다」이다.**

- 이유를 알면 → 위 셋 중 하나를 한 줄로 적는다.
- **답을 못 받았으면 횟수와 시점만 적고 이유는 비운다.** 원인을 비우는 편이 틀린
  원인을 붙이는 것보다 낫다.
- **「약한 자리」는 글쓴이가 그렇게 말했을 때만 쓴다.** AI가 판정하지 않는다.
  "중복이라 쓰지 않는다"는 규칙이 이미 있는데 "약하다"만 허용돼 있던 것은 같은 결함이었다.

마무리에서 학습 패턴을 짚는 것은 계속한다. 다만 **"몇 개가 몇 번째인가"까지가 사실이고,
"그래서 약하다"는 해석**이다. 사실만 쓰고 해석은 글쓴이 몫으로 남긴다.

횟수를 세는 방법 — 기존 용어정리 글들의 카드 제목을 뽑아 대조한다.

```bash
grep -h "^### " $(grep -l "categories: \[일지, 용어정리\]" _posts/*.md)
```

글 앞부분에 기준을 한 줄 밝히고, 마무리에서 **몇 개가 두 번째·세 번째인지**와
어떤 종류의 용어가 반복되는지(예: 구조·규칙을 가리키는 말) 짚으면 글이 스스로
학습 패턴을 드러낸다.

## 여러 개를 묶을 때 (= '오늘의 용어 정리' 글)
- 제목: `"오늘의 용어 정리 — 용어1·용어2·용어3"` (가운뎃점 `·`으로 나열)
- `categories: [일지, 용어정리]`, `tags:`에 각 용어를 그대로
- 카드를 `### 1.`부터 번호순으로 나열(10개 넘으면 갈래로 묶는다)
- 이전에 정리한 용어가 섞여 있으면 위의 **「다시 정리」 표시**를 붙인다
- Front matter는 [[jekyll-frontmatter]] 규칙을 따른다

## 출력
카드(들) 마크다운. 묶음 글이면 front matter + 파일명 `YYYY-MM-DD-terms-주제.md`까지 함께.
