# 학습 일지 회고 글 변환 (blog-retro)

> ⚠️ **먼저 [[lms-safe]]를 적용한다.** 입력이 LMS/강의 노드 노트면, 회고 글로 옮기기 전에 lms-safe 가드(원문 복붙·6어절 이상 연속 동일·코드 그대로·조기 공개 금지, 자체 소화 재작성)를 반드시 통과시킨다.

날것의 노트를 받아 조경호 블로그(GitHub Pages / Chirpy)의 회고 일지 한 편으로 완성한다.
결과물은 그대로 `_posts/`에 넣어 발행할 수 있어야 한다.

## 입력으로 받는 것
- 그날 배운 것 / 한 작업 메모 (순서·형식 무관, 거칠어도 됨)
- (있으면) 전날 글의 마지막 "다음 예고" 문장 → 오늘 도입부로 이어받는다

## 만드는 순서

1. **제목의 축을 정한다.** 그날 작업에서 가장 중요한 발견·반전 하나를 제목으로 세운다.
   - 은유형 제목은 **선택지의 하나일 뿐 의무가 아니다.** 은유가 그날의 핵심을 더 정확히
     드러낼 때만 쓴다. 그렇지 않으면 **발견 자체를 담은 담백한 제목**이 낫다.
     예: "파인튜닝이 1등이 아니었다", "copy baseline을 안 쟀으면 반대로 결론 낼 뻔했다".
   - 은유를 쓰기로 했다면 제목·도입부에서 자연스럽게 이어지되, 억지로 섹션마다
     끌고 다니지 않는다. 내용이 앞서고 은유는 거들 뿐이다.

2. **Front matter를 만든다.** → 세부 규칙은 [[jekyll-frontmatter]] 스킬을 따른다.
   - `title: "제목 — 한 줄 부제"` (제목은 은유형/담백형 중 그날 핵심을 더 잘 드러내는 쪽)
   - `categories:` 개념 정리 위주면 `[일지, 개발]`, 프로젝트 회고면 `[프로젝트]`
   - `description:` 전날 예고를 이어받아 "무엇을 한 날인지" 1~3문장

3. **도입부(1문단).** 전날 글의 예고를 받아 오늘 작업으로 잇는다.
   전날 예고가 없으면 그날의 문제의식으로 담백하게 연다.

4. **번호 섹션을 쌓는다.** `## 1.` `## 2.` … 순서로, 대체로 이 흐름:
   - 개념(무엇을·왜) → 구현(실제로 한 것) → 검증(확인한 방법) → 보안/주의 → 회고
   - **용어는 그대로 쓴다.** 이해가 실제로 걸리는 개념에만 비유를 절제해서 붙인다 → [[analogy-maker]].
     대부분의 용어는 비유 없이 그대로 두는 게 맞다.
   - 코드/명령은 인라인으로 두고 **화살표(→) 뒤에 한국어 설명**을 붙인다.

5. **로드맵 표(선택).** 프로젝트 시리즈 글이면 Phase 0~7 표에서 오늘 완료 단계를 표시.

6. **마무리.** "AI가 한 일 vs 내가 판단한 일" 정리로 닫고 → [[my-role]],
   마지막 줄에 **다음 예고 한 문장**을 남긴다(다음 글 도입부가 될 씨앗).

7. **말투 점검.** 전체를 조경호 특유의 톤으로 다듬는다 → [[tone-keeper]].

## 지켜야 할 톤
- 대화체·성찰형. "알고 가기", "실수도 했다" 같은 솔직한 자기 서술을 허용.
- 승리 자랑보다 **과정과 이해**를 강조(속도보다 이해).
- **정확한 용어가 먼저다.** 글쓴이는 용어를 알고 쓰므로 그대로 쓴다.
  비유는 이해가 실제로 걸리는 곳에만 보조로 얹는다(쉽게 풀기가 목적이 아니다).

## 출력
완성된 마크다운 전문(front matter 포함)과, 저장할 파일명 `YYYY-MM-DD-slug.md`를 함께 제시한다.
