# 개념 → 실습 연결 스킬 (concept-bridge)

목적: "그때 배운 개념이 여기서 이렇게 쓰였다"를 글 구조에 남긴다. 개념과 실습이 카테고리로만 갈라져 있으면 그 연결이 안 보이는데, 이 스킬은 그 다리를 명시적으로 놓는다.

## 언제 쓰나
- 실습 글(`[일지, 실습]` 또는 `[프로젝트, 개인프로젝트]`)을 새로 쓸 때
- 이미 발행된 실습 글에 소급 적용할 때 (사용자가 "이 글들에 개념 링크 달아줘"라고 요청할 때)

## 방법
1. 실습 글 본문에서 실제로 적용된 개념을 뽑는다 (예: 트랜잭션, Docker 컨테이너, IPv6, RLS 등). 지어내지 말고 본문에 실제로 등장하는 것만.
2. `_posts/`의 `[일지, 개념]` 글들 중 그 개념을 다루는 글을 제목·태그로 찾는다.
3. 매칭되면 실습 글의 **description 아래, 첫 섹션 시작 전**에 짧은 링크 박스를 추가한다:
   ```
   > 관련 개념: [개념 글 제목](/blog/posts/slug/)
   {: .prompt-info }
   ```
   개념이 여럿이면 가운데 점(·)으로 이어 붙인다. 핵심 2~3개로 추리고, 4개를 넘지 않는다.
4. 매칭되는 개념 글이 없으면 억지로 만들지 않고 생략한다 — 없는 연결을 지어내지 않는다.
5. 역방향(개념 글에 "이 개념이 쓰인 실습" 링크)은 기본적으로 하지 않는다. 개념 글 하나가 여러 실습에 걸쳐 쓰이면 링크가 계속 늘어나 글이 지저분해지기 때문 — 필요하면 사용자에게 먼저 확인한다.

## 체크리스트
- [ ] 링크가 실제로 존재하는 글(파일)을 가리키는가 — slug를 지어내지 않았는가
- [ ] 실습 글당 관련 개념이 4개를 넘지 않는가
- [ ] Chirpy prompt 박스 문법(`{: .prompt-info }`)이 맞는가
- [ ] 매칭되는 개념이 정말 없는 글에는 박스를 억지로 달지 않았는가

## draft-to-post와의 관계
[[jekyll-frontmatter]]로 slug·categories가 확정된 뒤, [[tone-keeper]] 최종 교정 전에 — 글이 실습 카테고리일 때만 이 스킬을 거친다.
