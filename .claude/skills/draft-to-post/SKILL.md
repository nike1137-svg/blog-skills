# 초안 → 발행 완성 파이프라인 (draft-to-post)

> ⚠️ **0단계: 먼저 [[lms-safe]]를 적용한다.** 입력이 LMS/강의 노트면, 파이프라인을 돌리기 전에 원문 복붙·6어절 이상 연속 동일 표현·코드 그대로 게시·조기 공개를 막는 lms-safe 가드를 반드시 통과시킨다. 게시 전 lms-safe 체크리스트도 통과해야 한다.

노트만 던지면 `_posts/`에 바로 넣을 수 있는 글 한 편을 끝까지 만든다.
개별 스킬을 아래 순서대로 호출·조합하는 **오케스트레이터**다.

## 파이프라인

1. **글 종류 판별**
   - 개념/작업 회고 → 일지 글, 용어 여러 개 → '오늘의 용어 정리' 글.
   - 용어 글이면 [[term-card]]로 넘겨 카드들을 만든 뒤 5번(front matter)으로.

2. **본문 구성** → [[blog-retro]]
   은유 정하기 → 도입부 → 번호 섹션(개념→구현→검증→보안→회고) → (프로젝트면 로드맵 표).

3. **어려운 대목 비유 보강** → [[analogy-maker]]
   전문 용어가 처음 나오는 자리마다 일상 비유 한 줄.

4. **마무리** → [[my-role]]
   "AI가 한 일 vs 내가 판단한 일" 정리 + 다음 예고 한 문장.
   ⚠️ **다음 예고는 글쓴이에게 물어서 받는다. 지어내지 않는다.**
   그럴듯해 보여도 추측해서 쓰면 다음 글이 그 예고를 정정하며 시작해야 한다.

5. **파일명 + Front matter** → [[jekyll-frontmatter]]
   제목·카테고리·태그·날짜·설명 확정, `_posts/YYYY-MM-DD-slug.md` 결정.

6. **과거 글과 잇기** → [[concept-bridge]]
   회고·실습 성격이면 **카테고리를 가리지 않고** 거친다(메인퀘스트·과제 포함).
   `_posts/`를 **실제로 grep해서** 두 가지를 찾는다.
   - 이 글이 적용한 `[일지, 개념]` 글 → "관련 개념" 링크 박스
   - **과거에 내가 내린 결론 중 오늘 것과 이어지는 것** → 본문에서 그때 문장을 인용해 잇는다
   찾아본 결과 정말 없으면 생략한다. 다만 **안 찾아보고 없다고 하지 않는다.**

7. **말투 최종 교정** → [[tone-keeper]]
   과장 제거, 은유 일관성, 마지막 여운 확인.

## 산출물 (한 번에 제시)
- 저장 경로/파일명: `_posts/YYYY-MM-DD-slug.md`
- front matter 포함 마크다운 **전문**
- 발행 전 셀프 체크:
  - [ ] 전날 예고를 이어받았는가
  - [ ] 어려운 용어마다 비유가 있는가
  - [ ] 마무리에 '내 판단'과 '다음 예고'가 있는가
  - [ ] **다음 예고가 글쓴이에게 물어서 받은 실제 계획인가** — 지어낸 것이면 지운다
  - [ ] categories가 2단계인가, date에 `+0900`이 있는가
  - [ ] **date가 실제 현재 시각보다 과거인가** (미래면 Jekyll이 빌드에서 빼서 404 — 시스템 시계로 확인)
  - [ ] 관련 개념 링크가 실제 존재하는 글을 가리키는가 — 없으면 억지로 달지 않았는가
  - [ ] **과거 글을 실제로 grep해봤는가** — 오늘 결론과 이어지는 예전 결론이 있는지.
        인용했다면 원문과 글자까지 대조했는가

## 원칙
확정이 애매한 값(제목 은유·카테고리·slug)은 지어내지 말고 후보를 제시해 고르게 한다.
