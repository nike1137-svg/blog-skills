# 이해 보조 비유 생성 (analogy-maker)

> **전제(2026-08-26 갱신): 비유는 기본값이 아니라 예외다.**
> 글쓴이는 이제 대부분의 용어를 정확히 이해하고 쓴다. 비유의 목적은
> "비전문가도 읽히게 쉽게 풀기"가 **아니라**, **이해가 실제로 걸리는 지점에서만**
> 그 걸림을 풀어주는 것이다. 용어는 그대로 쓰고, 비유는 보조로만 얹는다.

기술 개념 하나를 받아, 정말 필요할 때 **이해를 돕는 비유 한 줄**을 만든다.

## 먼저 — 비유를 붙일지부터 판단한다
아래에 하나라도 해당하면 **비유를 붙이지 않는다.** 용어를 그대로 쓴다.
- 글쓴이가 이미 다른 글에서 쓰는 어휘다 → [[tone-keeper]]의 「이미 익숙한 어휘」 참고.
- 용어의 이름만으로 동작이 대충 짐작되는 것(예: 자동 시작, 재시도, 로그).
- 그 글에서 이미 한 번 비유를 쓴 개념 — 반복해서 비유하지 않는다.

비유는 **처음 나오는, 동작이 직관에 어긋나거나 오해하기 쉬운 개념**에만 붙인다.
한 글에 비유가 두세 개를 넘으면 과하다. 없는 게 맞는 글도 많다.

## 붙이기로 했다면 — 좋은 비유의 조건
- **손에 잡히는 사물/행동**에 빗댄다: 계산대 옆 바구니, 창고, 책 뒤 색인, 레시피, 문과 자물쇠, 상자.
- 개념의 **핵심 동작 한 가지**만 정확히 대응시킨다(너무 많이 갖다 붙이지 않는다).
- 비유가 **어디서 깨지는지**도 한 줄로 덧붙이면 더 좋다(정직한 서술).
- 추상 비유("흐름처럼", "마법같이") 금지. 전문 용어로 전문 용어를 설명하지 않는다.
- **용어를 대체하지 않는다.** 정확한 용어를 먼저 쓰고, 비유는 그 옆에 보탠다.

## 블로그 실제 비유 (톤 레퍼런스)
- 캐시 → "자주 찾는 물건을 **계산대 옆 바구니**에 올려 둠"
- 색인(인덱스) → "책 뒤 **색인**에서 단어 찾듯, 처음부터 안 넘겨도 됨"
- SQL 인젝션 → "레시피에 몰래 한 줄 끼워 넣어 엉뚱한 요리를 시키는 것"
- 배포 터널 → "안에서 밖으로 낸 **터널**, 문은 나만 들어가게 잠금"

## 출력 형식
개념마다:
```
- **비유**: (일상 사물/행동에 빗댄 한 문장)
- (선택) **어디서 깨지나**: (비유의 한계 한 줄)
```
필요하면 후보 2~3개를 주고 고르게 한다.
