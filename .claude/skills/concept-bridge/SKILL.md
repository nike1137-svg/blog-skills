# 과거 글과 잇기 (concept-bridge)

목적이 둘이다.

1. **"그때 배운 개념이 여기서 이렇게 쓰였다"** — 개념과 실습의 다리
2. **"그때 내가 내린 결론이 오늘 작업과 이어진다"** — 결론과 결론의 다리

두 번째는 2026-08-31에 추가됐다. 그날 실제로 이런 일이 있었다. 나흘 전 글에
**"파인튜닝과 RAG가 보완재"**라고 써 두고도, 그날 한 메인퀘스트가 바로 그 문장의
오른쪽 절반이라는 걸 못 보고 글을 끝낼 뻔했다. 글쓴이가 먼저 물어서야 드러났다.

글이 쌓이면 **각 글은 그날 안에서 닫힌다.** 나흘 전 결론이 오늘 작업과 이어지는지는
누가 찾아보지 않으면 보이지 않는다. 이건 글쓴이가 이해를 못 해서가 아니라 글이
흩어져 있어서 생기는 일이므로, **찾는 일을 사람 기억에 맡기지 않는다.**

## 언제 쓰나

**회고·실습 성격의 글이면 카테고리를 가리지 않고 전부 거친다.**

`[일지, 실습]` · `[일지, 개념]` · `[일지, 회고]` ·
`[프로젝트, 개인프로젝트]` · `[프로젝트, 메인퀘스트]` · `[프로젝트, 과제]`

> 2026-08-31 확대. 그전에는 `[일지, 실습]`과 `[프로젝트, 개인프로젝트]` 둘만
> 대상이라 **메인퀘스트 글이 통째로 빠져나갔다.** 위의 누락이 거기서 났다.

용어정리(`[일지, 용어정리]`)와 일상(`[일지, 일상]`)은 대상이 아니다.
이미 발행된 글에 소급 적용할 때도 같은 규칙을 쓴다.

## 0단계 — 저장소를 실제로 뒤진다 (건너뛰지 않는다)

**기억이나 짐작으로 하지 않는다.** 오늘 글에서 핵심 낱말·수치·결론 문장을 뽑아
각각 찾아본다.

```bash
grep -rl "<핵심어>" _posts | sort | tail -20        # 어느 글에 있나
grep -n "<핵심어>" _posts/<후보>.md                  # 그 글에서 무슨 말을 했나
```

뽑을 것의 예 — 그날 다룬 기술 이름(`RAG` `파인튜닝` `프롬프트` `임계값`),
그날 나온 수치(`20.7초` `6.5배`), 프로젝트 이름(`온담이`), 그날의 결론 낱말.

- 후보가 나오면 **그 대목을 열어 실제로 무슨 말을 했는지 읽는다.** 제목만 보고 판단하지 않는다.
- 오늘 결론과 **반대되는** 말을 과거에 했다면 그것도 연결이다. 오히려 더 좋은 연결이다.

## (가) 관련 개념 — 링크 박스

1. 글 본문에서 실제로 적용된 개념을 뽑는다 (트랜잭션, Docker 컨테이너, IPv6, RLS 등).
   지어내지 말고 본문에 실제로 등장하는 것만.
2. `_posts/`의 `[일지, 개념]` 글 중 그 개념을 다루는 글을 찾는다.
3. 매칭되면 **description 아래, 첫 섹션 시작 전**에 짧은 링크 박스를 넣는다.
   ```
   > 관련 개념: [개념 글 제목](/blog/posts/slug/)
   {: .prompt-info }
   ```
   개념이 여럿이면 가운데 점(·)으로 잇는다. 핵심 2~3개로 추리고 4개를 넘지 않는다.
4. 매칭되는 개념 글이 없으면 **억지로 만들지 않고 생략한다.**

## (나) 과거 결론 — 본문에서 인용해 잇기

오늘 글의 결론이 과거 글의 결론과 이어지면, 링크만 걸지 말고 **그때 쓴 문장을
인용해서** 잇는다. 링크는 눌러야 보이지만 인용은 그 자리에서 읽힌다.

들어갈 자리는 대체로 둘이다.

- **본문 중간** — 오늘 잰 값이 과거에 잰 값과 이어지거나 어긋날 때, 그 절 안에서
- **"다음은" 앞** — 오늘 한 일이 과거 결론의 어느 부분이었는지 자리매김할 때

쓰는 모양:

```markdown
나흘 전 글([제목](/blog/posts/slug/))에서 이렇게 적었다.

> (그때 문장 그대로)

(오늘 것이 그 문장과 어떻게 이어지는지 한두 문장)
```

**인용은 원문과 글자를 대조한다.** 기억으로 옮겨 적지 않는다.

```bash
grep -o "인용하려는 문장 앞부분" _posts/<그 글>.md
```

숫자가 비슷해서 같은 것으로 보이지만 실은 다른 것이면, **다르다는 것을 밝히는 게
연결이다.** (실제 예: 20.7초는 답을 쓰는 시간, 19~21초는 질문을 읽는 시간 — 손잡이가 다르다.)

## 체크리스트

- [ ] **0단계 grep을 실제로 돌렸는가** — 안 돌리고 "연결 없음"이라고 하지 않았는가
- [ ] 링크가 실제로 존재하는 글(파일)을 가리키는가 — slug를 지어내지 않았는가
- [ ] 인용문이 **원문과 글자까지 같은가**
- [ ] 관련 개념이 4개를 넘지 않는가
- [ ] Chirpy prompt 박스 문법(`{: .prompt-info }`)이 맞는가
- [ ] 없는 연결을 억지로 만들지 않았는가 — **정말 없으면 없는 게 맞다**

## 하지 않는 것

역방향(개념 글에 "이 개념이 쓰인 실습" 링크)은 기본적으로 하지 않는다.
개념 글 하나가 여러 실습에 걸치면 링크가 계속 늘어나 글이 지저분해진다.
필요하면 글쓴이에게 먼저 확인한다.

## draft-to-post와의 관계

[[jekyll-frontmatter]]로 slug·categories가 확정된 뒤, [[tone-keeper]] 최종 교정 전에 거친다.
**회고·실습 성격이면 카테고리를 가리지 않고 거친다.**
