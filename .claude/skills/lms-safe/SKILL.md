# LMS 저작권 준수 가드 (lms-safe)

목적: **LMS 노드(강의) 내용을 블로그로 옮길 때** 모두의연구소 저작권/게시 정책을 자동으로 지킨다.
블로그 글 생성 스킬([[term-card]] · [[blog-retro]] · [[draft-to-post]])을 쓰기 **전에, 항상 먼저** 적용한다.

## 왜 (배경)
LMS 노드 콘텐츠는 **복제·제3자 전달 금지**다. **공개 블로그 게시 = 제3자 전달**이라, 정책은 "자체적으로 소화한 내용"만 규칙에 맞게 게시하도록 허용한다. 즉 문제는 '블로그'가 아니라 '복붙'이다. 방식만 지키면 계속 기록해도 된다.

## 절대 규칙 (하나라도 어기면 게시 불가)
1. **원문은 참고만.** LMS 텍스트를 옮겨 쓰지 않는다. 읽고 이해한 뒤 **완전히 내 말로 재작성**.
2. **6어절 / 1문장 이상 연속 동일 표현 금지.** (예외: `MVP`·`RLS`·`HTTP` 같은 **공인된 전문 용어 자체**는 허용.)
3. **코드·주석 그대로 게시 금지.** 노드가 제공한 코드를 그대로/일부 그대로 나열 금지. **내가 변형·추가한 코드만**, 설명은 내 문장으로.
4. **출처 목록·통계 문장 복붙 금지.** 필요하면 **원 출처를 직접 확인해** 내 문장으로 쓴다.
5. **공개 시점:** 해당 노드의 **제출 기한 + 루브릭 평가 완료 이후에만** 공개. 그 전에는 **비공개 초안**으로만 저장.
6. **정의·비유·예시도 재현 금지.** 노드의 정의/예시를 베끼지 말고 내가 이해한 대로 새로 쓴다.

## 작성 방법 — '자체 소화'
- 원문을 덮고, **머릿속에서 핵심만 다시 설명한다**는 마음으로 쓴다.
- 흐름: 개념 → **내가 이해한 것** → **내 경험·적용·판단**. (설명의 재현이 아니라 소화의 결과)
- 비유·예시는 **새로** 만든다(원문 비유 재사용 금지) → [[analogy-maker]].
- 강한 글은 원문 요약이 아니라 **"나는 이걸 이렇게 이해했고, 어디에 쓸 것 같다"** 다.

## 게시 전 자체 점검 (필수 체크리스트)
커밋/공개 전에 반드시 확인하고, 하나라도 걸리면 고친다:
- [ ] 원문과 **6어절 이상 연속 겹치는 문장**이 없는가? (의심되면 그 문장 재작성)
- [ ] 노드 **코드·주석을 그대로** 넣지 않았는가?
- [ ] **출처·수치 문장을 복붙**하지 않았는가?
- [ ] (공개라면) **제출 기한 + 루브릭 평가 완료 이후**인가? 아니면 **비공개 유지**.
- [ ] 전체가 **"내가 소화한 내용"**으로 읽히는가? (원문 요약처럼 읽히면 다시 쓴다)

## 애매하면
- 공개하지 말고 **비공개 초안**으로 두고, 사용자에게 알린다.
- 정책 해석이 불확실하면 **운영진 확인**을 권한다. (이 스킬은 정책 문서 기준의 가이드이지 공식 유권해석이 아니다.)

## 출력
- 재작성된 글(자체 소화본) + 위 **체크리스트 통과 여부** 표시.
- 공개 시점 미충족이면 **"비공개 초안"** 으로 권고.
